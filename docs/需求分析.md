# 旅游智能体助手 需求分析

> 分析依据：《旅游智能体项目技术文档》、项目演示视频（152 秒，已逐帧拆解，关键帧存于 `video/frames/`）、现有代码走查
> 分析日期：2026-10-02

---

## 一、项目概述

开发一个"AI旅游智能助手"Web 应用：用户用自然语言提出旅行需求（如"规划福州到杭州 6 天 5 夜自驾游"），系统由总控智能体调度多个子智能体（路线/酒店/交通/天气），调用高德开放平台真实 API 获取数据，最终在聊天界面输出结构化的旅行方案（含路线分段、沿途景点图片、按天行程建议表）。

**项目定位**：教学级多智能体项目，技术选型以"简单高效、易吸收"为原则。

### 2.2 演示的业务流程

用户提问："请帮我规划从福建省福州市福州飞南路86号到浙江省杭州市雷锋塔进行6天5夜自驾游路线"

助手回复过程（气泡内可见的推理链）：
1. **任务分析**：提取起点/终点/行程（6天5夜）/方式（自驾）
2. **智能体编排**：自我定位"旅游总控"，列出需调度的子智能体——路线规划→`route_planning_agent`、酒店搜索→`hotel_search_agent`、交通查询→`traffic_query_agent`
3. **参数提取**：输出 JSON（startCity / origin_address / endCity / dest_address / travel_mode / travel_days / preference）
4. **容错重试**：首次调用高德地理编码报错（城市名带"市"）→ 自动改为"福州/杭州"重试成功

### 2.3 最终回复结构（核心验收标准）

| 模块 | 内容要点 |
|---|---|
| 【自驾总览】 | 起终点坐标、总里程 596km、总时长 7.3h、过路费 294 元、策略"速度最快" |
| 【分段行程】 | 9 个聚合大段：区间名称→里程→时长→道路类型→配套设施（收费站数）→路况提示（隧道群提醒） |
| 【出行提示】 | 隧道灯光切换、山路雨天防滑、提前加油、山区信号弱建议离线地图、长途建议 2-3 个停留点 |
| 【沿途景点推荐】 | 湖滨步行街、in77、龙湖滨江天街、万象城、大悦城等，每个含类型/评分/门票/开放时间表格 **+ autonavi 图片** |
| 【终点景点】 | 雷峰塔：位置/类型/推荐指数★★★★★/门票约40元/开放时间（旺季淡季）/停车 + 游玩建议（雷峰夕照） |
| 【6天5夜行程建议】 | 表格：Day1 福州→宁德(130km,住宁德品海鲜) / Day2→丽水(古堰画乡) / Day3→金华(火腿) / Day4→诸暨(西施故里) / Day5→杭州(西湖) / Day6 游玩返程 |
| 【沿途游玩/住宿建议】 | 霞浦滩涂、古堰画乡、金华美食 |
| 结尾 | "祝您旅途愉快" |

## 三、技术架构（技术文档已定）

```
浏览器 (HTML/CSS/JS)
   │  POST /chat
FastAPI (main.py, uvicorn)
   │  openai-agents SDK (Runner/handoffs/function_tool)
Agent_com/ 总控智能体 + 子智能体
   │
skill/ 技能层
   │
mcp_tools/ MCP 工具层 (Pydantic schema 清洗)
   │
高德开放平台 Web API（地理编码/驾车路线/天气/POI搜索）
```

- 大模型：阿里通义千问（DashScope OpenAI 兼容接口，`.env` 配置 DASHSCOPE_API_KEY / DASHSCOPE_BASE_URL / MODEL_NAME）
- Agent 四层认知：感知（用户输入）→ 认知（LLM）→ 执行（工具，40% 工作量）→ 记忆（会话，60% 工作量）
- 多智能体协作机制：**Handoffs 交接**（SDK 自动生成 `transfer_to_xxx_agent` 虚拟工具）

## 五、已知代码缺陷（开发前必须修复）

1. **`amap_mcp.py aggregate_steps()`**：except 块引用未定义变量 `e` → 景点检索异常时触发 NameError
2. **WeatherMCP**：
   - GeomMCP 返回经纬度却当 adcode 传给天气接口的 city 参数（应取 adcode）
   - `AmapWeatherResponse.model_validate(res["now"])` 结构不匹配（now 是实况 dict，缺 status/info 等必填字段，校验必失败）
3. **HotelSearchMCP**：
   - 首次请求期望 `res["geocode"]`，但 `place/around` 接口无此字段 → KeyError
   - `price_min/price_max/crowd/stay_days` 不是高德合法请求参数
   - 实例化 `SigleHotelItem(avg_price=...)`，schema 里字段名是 `price` → TypeError
   - `HotelSearchOutput.total_suggest` 声明为 str，却传入 int
4. **schemas.py**：`BudgetSearchParms.food_cost` 重复定义；`from ctypes import addressof` 无用导入
5. **main.py**：MonitorHooks 未挂载到 Runner.run

## 六、功能需求清单

### FR1 前端界面（视频同款）
- FR1.1 全屏布局：左侧深色会话栏 + 主聊天区
- FR1.2 会话栏：新建对话按钮、历史会话列表（标题=首条用户消息截断）
- FR1.3 消息气泡：用户右蓝 / 助手左灰
- FR1.4 Markdown 渲染：标题、表格、列表、引用、emoji
- FR1.5 图片渲染：高德 autonavi CDN 图片直接显示
- FR1.6 输入区：placeholder + 发送按钮 + 回车发送 + 请求中禁用
- FR1.7 "思考中…"加载状态
- FR1.8 回到底部悬浮按钮

### FR2 会话管理
- FR2.1 后端按 user_id + 会话 ID 维护独立对话历史
- FR2.2 新建会话 / 切换会话不串上下文

### FR3 路线规划智能体（核心）
- FR3.1 输入解析：起点城市+详细地址、终点城市+详细地址、出行方式、天数、偏好
- FR3.2 必须调用高德驾车路线 API，禁止编造路线
- FR3.3 输出六大模块：自驾总览 / 分段行程 / 出行提示 / 沿途景点(带图) / 终点景点(带图) / N天M夜行程建议表 + 沿途游玩住宿建议
- FR3.4 地理编码失败时自动修正参数重试（如去掉城市名后缀"市"）

### FR4 酒店智能体
- FR4.1 修复 HotelSearchMCP：正确调用高德 POI 周边搜索，返回酒店名/地址/价格/评分
- FR4.2 hotel_agent 挂载工具，真实 POI 数据驱动推荐

### FR5 交通智能体
- FR5.1 根据出发地/目的地/日期给出交通方式建议（飞机/高铁）
- FR5.2 数据源待确认（见"待确认问题 2"）

### FR6 天气智能体
- FR6.1 修复 WeatherMCP（adcode 正确传递、schema 匹配）
- FR6.2 天气查询能力接入总控调度

### FR7 总控智能体
- FR7.1 意图识别 → handoff 分发到对应子智能体
- FR7.2 全程中文输出

- NFR6 每个开发阶段一次 git 提交，可回滚
