## 二、通用约束（每轮都适用，务必先读）

**环境阻塞规避（最高优先级）**
- 不要用后台方式在 agent 会话里常驻启动 `python main.py`，会触发 `Toolhost lifecycle is blocked`，只能重启 TRAE 恢复。
- 服务由用户在自己的终端启动；agent 只跑短命令。
- 若必须由 agent 起服务：关掉 uvicorn `reload`、用单独脚本 start/stop、跑前台命令前先停服务、不复用正在跑服务的终端。

**工作方式**
- 以阶段为单位推进，完成一个阶段再测试
- 一个步骤一次提交 + 一份验收证据，提交完停下等审核
- 全程中文输出；提交后 `git push origin main`

**已实测技术事实（避免重复踩坑）**
- 天气：`/v3/weather/weatherInfo?city={adcode}&extensions=base|all`；`city` 必须是 **adcode**；实时在 `lives`，预报在 `forecasts[0].casts`
- 驾车：`path.tolls` 恒为 `"0"`，过路费用 `toll_distance × 0.45` 估算
- 途经城市在 `step.cities`，`route.cities` 恒空（需 `extensions=all`）
- 道路类型需结合 `instruction` 判断（`road` 多为隧道/枢纽名）
- POI 编码：风景名胜 `110000`、餐饮 `050000`、住宿 `100000`（`060000` 是购物服务，别用）
- 交通：聚合数据**按接口分配 appkey**，火车用 `JUHE_TRAIN_KEY`、航班用 `JUHE_FLIGHT_KEY`；火车 `apis.juhe.cn/fapigw/train/query`（站点名查询，仅限未来 15 天），航班 `apis.juhe.cn/flight/query`（出发/到达须 IATA 三字码）
- `.env` 改动不会触发 uvicorn reload，改完必须手动重启服务
- 模型偶发返回非法工具参数 JSON，重试可恢复

## 四、各轮次详情

### P1 前端重构 ✅

目标：把原布局重构为视频同款聊天式界面（左侧会话栏 + 主对话区 + 输入区），浅色克制风格。
涉及：`index.html`、`static/css/style.css`、`static/js/app.js`、`static/js/markdown.js`
验收：页面可正常对话，Markdown 表格/代码/列表渲染正确。

### P2 会话隔离 ✅

目标：按 `session_id` 隔离后端对话记忆，前端支持新建/切换会话并 localStorage 持久化。
涉及：`main.py`（`ChatRequest` 加 `session_id`、`SQLiteSession`）、`static/js/app.js`
验收：多会话互不串上下文，刷新后会话保留。

### P3 路线输出对齐 ✅

目标：修复路线输出与预期的 5 处差距：分段过碎、首段名称异常、途经城市为空、过路费为 0、景点错位。
涉及：`mcp_tools/amap_mcp.py`
验收：`tests/p3_route_verify.py` 输出 4~5 段、真实起终点名、6 座途经城市、过路费非 0、景点按城市就位。

---

### P4 天气接入 ✅

目标：接入高德天气，支持实时天气与未来预报。
涉及：`mcp_tools/amap_mcp.py`（重写 `WeatherMCP` + 新增 `GeomMCP.get_adcode`）、`skill/weather_skill.py`、`Agent_com/weather_agent.py`、`Agent_com/main_agent.py`、`tests/p4_weather_verify.py`
要点：天气接口 `city` 必须是 **adcode**（传经纬度报错）；实时数据在 `lives`、预报在 `forecasts[0].casts`
验收：`tests/p4_weather_verify.py` 输出杭州实时天气 + 大理未来 3 天预报；`/chat` 天气问答返回真实数据。
补充修复：`01fd67c` 修复起终点地址为空时地理编码报 `INVALID_PARAMS`。
